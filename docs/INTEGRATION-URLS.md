# Integration URL update: Floot → Supabase

Your Stripe, Google, Square, GoCardless and HighLevel apps still point at the old Floot app. This sheet lists every URL to change, where to change it, and the secret each value goes into.

**New API base (replaces `https://localservicepro.floot.app/_api`):**

```
https://gcuzmuztikisxsmkgtbi.supabase.co/functions/v1/api
```

**New web app (replaces `https://localservicepro.floot.app`):**

```
https://home.localservicepro.com.au
```

The secret names are the **same ones Floot used**, so you can copy each value straight across from Floot's secrets. Add them in **Supabase → project gcuzmuztikisxsmkgtbi → Edge Functions → Secrets → Add new secret**. They take effect on the next request; you don't need to redeploy.

A safe order is to add the new URL alongside the old one, test, then remove the old one. Every provider below accepts more than one redirect URL.

---

## 1. Stripe

Stripe has three URLs: one OAuth redirect and two webhooks. Do it in **Test mode** first, then repeat in **Live mode**, which keeps its own settings.

| What | Old (Floot) | New |
| --- | --- | --- |
| Connect OAuth redirect | `https://localservicepro.floot.app/_api/stripe/callback` | `https://gcuzmuztikisxsmkgtbi.supabase.co/functions/v1/api/stripe/callback` |
| Webhook: connected accounts (invoice payments) | `https://localservicepro.floot.app/_api/stripe/webhook` | `https://gcuzmuztikisxsmkgtbi.supabase.co/functions/v1/api/stripe/webhook` |
| Webhook: your account (subscriptions) | `https://localservicepro.floot.app/_api/stripe/billing_webhook` | `https://gcuzmuztikisxsmkgtbi.supabase.co/functions/v1/api/stripe/billing_webhook` |

**Where to change them:**
1. **OAuth redirect:** Settings → Connect → Onboarding options → OAuth → Redirects. Add the new URL, then remove the old one once you've tested.
2. **Webhooks:** Developers → Webhooks. Open each Floot endpoint → **⋯ → Update details** and change the **Endpoint URL**. The signing secret stays the same when you edit an endpoint.
   - The **connected accounts** endpoint listens to `checkout.session.completed` and `checkout.session.async_payment_succeeded`.
   - The **your account** endpoint listens to `checkout.session.completed`, `invoice.paid`, `invoice.payment_failed`, `customer.subscription.created`, `customer.subscription.updated` and `customer.subscription.deleted`.

**Secrets:**

| Secret | Where to find it |
| --- | --- |
| `STRIPE_SECRET_KEY` | Developers → API keys → Secret key (`sk_test_…` / `sk_live_…`) |
| `STRIPE_CLIENT_ID` | Settings → Connect → Onboarding options → OAuth → Client ID (`ca_…`) |
| `STRIPE_WEBHOOK_SECRET` | The connected-accounts webhook → Signing secret (`whsec_…`) |
| `STRIPE_BILLING_WEBHOOK_SECRET` | The your-account webhook → Signing secret (`whsec_…`) |

The Billing return URLs (checkout and customer portal) are generated by the app on each request, so there's nothing to change for them in Stripe.

## 2. Google (Cloud Console)

There are up to two OAuth clients here. One is **Calendar sync**. The other is **"Continue with Google" sign-in**, which now goes through Supabase Auth instead of the app.

| What | Old (Floot) | New |
| --- | --- | --- |
| Calendar OAuth redirect URI | `https://localservicepro.floot.app/_api/gcal/callback` | `https://gcuzmuztikisxsmkgtbi.supabase.co/functions/v1/api/gcal/callback` |
| Sign-in OAuth redirect URI | `https://localservicepro.floot.app/_api/auth/google/callback` | `https://gcuzmuztikisxsmkgtbi.supabase.co/auth/v1/callback` |
| Authorised JavaScript origin | `https://localservicepro.floot.app` | `https://home.localservicepro.com.au` |

**Where to change them:** console.cloud.google.com → **APIs & Services → Credentials** → click each OAuth 2.0 client.
- Under **Authorised redirect URIs**, add the new URI, and remove the Floot one after testing.
- Under **Authorised JavaScript origins**, add `https://home.localservicepro.com.au`.
- Click **Save**. Changes can take a few minutes to apply.

Also check **OAuth consent screen → Branding**. The authorised domains should include `localservicepro.com.au`, and `supabase.co` is needed for the sign-in client's redirect.

**Secrets and settings:**

| Use | Where it goes |
| --- | --- |
| Calendar client | Secrets `GCAL_CLIENT_ID` and `GCAL_CLIENT_SECRET`. If Floot only had `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` and you use one client for both, set those two instead; Calendar falls back to them. |
| Sign-in client | **Not a secret.** Go to Supabase → **Authentication → Sign In / Providers → Google**, turn it on, and paste the client ID and secret. |
| Google reviews (Places API) | Secret `GOOGLE_MAPS_API_KEY`, the same key as before. It has no redirect URL. |

If you use one OAuth client for both sign-in and Calendar, it needs **both** new redirect URIs.

## 3. Square

| What | Old (Floot) | New |
| --- | --- | --- |
| OAuth redirect URL | `https://localservicepro.floot.app/_api/square/callback` | `https://gcuzmuztikisxsmkgtbi.supabase.co/functions/v1/api/square/callback` |
| Webhook notification URL | `https://localservicepro.floot.app/_api/square/webhook` | `https://gcuzmuztikisxsmkgtbi.supabase.co/functions/v1/api/square/webhook` |

**Where to change them:** developer.squareup.com → **Applications → your app**. Pick **Sandbox** or **Production** with the toggle at the top; each has its own settings.
1. **OAuth** → Redirect URL → set it to the new URL → Save. Square allows only one, so this is a swap.
2. **Webhooks → Subscriptions** → edit the subscription → set **Notification URL** to the new URL. The events are `payment.created` and `payment.updated`.
   - Webhook signatures are calculated over this exact URL, so paste it character for character, with no trailing slash.
   - If you create a new subscription instead of editing, it gets a **new signature key**, and you'll need to update the secret.

**Secrets:**

| Secret | Where to find it |
| --- | --- |
| `SQUARE_APP_ID` | Credentials → Application ID. If it starts with `sandbox-`, the app uses Square's sandbox automatically. |
| `SQUARE_APP_SECRET` | Credentials → Application secret |
| `SQUARE_WEBHOOK_SIGNATURE_KEY` | Webhooks → your subscription → Signature key |

## 5. HighLevel / LeadConnector (GHL)

| What | Old (Floot) | New |
| --- | --- | --- |
| OAuth redirect URL | `https://localservicepro.floot.app/_api/crm/callback` | `https://gcuzmuztikisxsmkgtbi.supabase.co/functions/v1/api/crm/callback` |
| Default webhook URL | `https://localservicepro.floot.app/_api/crm/webhook` | `https://gcuzmuztikisxsmkgtbi.supabase.co/functions/v1/api/crm/webhook` |

**Where to change them:** marketplace.gohighlevel.com → **My Apps → your app**.
1. **Advanced Settings → Auth → Redirect URL:** add the new URL → Save. Keep the scopes:
   - `locations.readonly`
   - `contacts.readonly`
   - `contacts.write`
   - `opportunities.readonly`
   - `opportunities.write`
2. **Advanced Settings → Webhooks → Default webhook URL:** set it to the new URL. The events are **OpportunityCreate** and **AppUninstall**.
3. If the app is published or under review, save the changes as a new version so they take effect.

**Secrets:**

| Secret | Where to find it |
| --- | --- |
| `LC_CLIENT_ID` | Auth → Client keys → Client ID |
| `LC_CLIENT_SECRET` | Auth → Client keys → Client secret (add a new one if you didn't keep the old) |

`GHL_PUBLIC_KEY` is no longer needed. Webhook signatures are checked with HighLevel's published public key, which is built into the app.

2. Under **Configuration → Redirect URIs**, add the new URI.

Secrets: `XERO_CLIENT_ID`, `XERO_CLIENT_SECRET` and `XERO_WEBHOOK_KEY`.
